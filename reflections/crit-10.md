# Crit 10 — Fly by instruments

## What was the breakthrough that moved the work forward?

Being a big project and all, and with lots of ideas that kept coming to me and I wanted to implement, I needed to get these running in parallel, rather than sequentially. I discussed with Claude the tasks/features I wanted to implement, then came up with markdown files for each of these, telling Claude to pick an appropriate model for the task at hand (Sonnet or Opus) and start implementing it in their respective sessions, figuring out the order and dependecies between task by itself. Whilst workflows this have increased the output I am getting, I have also noticed that myself sometimes not knowing, or remembering, how a feature was implemented/works, for example, with the tennis swing I could not remember which parts of the hand/arm were tracked, when I was considering how to tune the swings. A simple prompt asking the implementation did get me back on speed, but this is just something interesting I noticed.

## What did this work change about who I want to be as a software developer?

I have been someone who pays attention to how things work, what the logic is, and so forth, especially with AI coding. I like to know how things function so I am able to better build on implementations, or fix them, for example, with the tennis swing, knowing how the swinging worked helped me check if the implementation was at fault, or me with how I was trying to swing. However, with AI getting so good at coding and now the expectation of code output being larger, due to these tools, especially building very large projects in shorts amounts of time, knowing the backend about everything is becoming harder and harder to keep up with. I want to be a software developer that can hold that balance, and not feel fully detached from the entire build process.
